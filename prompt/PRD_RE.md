# 소년 상하좌우 이동 및 방향 전환 — 개발 PRD

## 1. 목적과 범위

방향키로 소년을 상하좌우로 이동시키고, 입력 및 이동 상태에 따라 애니메이션을 표시하는 프로그램을 구현한다. 캐릭터 전체가 화면 안에 머물러야 하며, 원본 PRD의 채점 기준인 **상하좌우 이동, IDLE 애니메이션, 화면 경계 제한**을 충족해야 한다.

이번 개발 범위는 이동, 좌우 방향 유지·전환, 애니메이션, 배경 표시까지이다. 이동 시 달리기 애니메이션을 사용하며, 별도 달리기 입력이나 속도 전환, 전투, 점수, 추가 화면 등의 기능은 포함하지 않는다.

## 2. 개발 환경과 리소스

- 기존 `Script` 예제와 동일하게 Python과 pico2d를 사용한다.
- 캐릭터: `Resourse/animation_sheet.png`
- 배경: `Resourse/TUK_GROUND.png`
- 화면 크기: 기존 배경 예제의 1280 × 1024를 기본값으로 사용한다.
- 시작 위치: 화면 중앙. 초기 바라보는 방향은 오른쪽으로 설정한다.
- 리소스 경로는 실행 위치에 의존하지 않도록 소스 파일 위치를 기준으로 계산한다.

화면 크기와 초기 방향은 원본에 지정되지 않은 구현 기본값이다. 이동 속도와 애니메이션 속도는 각각 상수로 분리하여 조정할 수 있게 한다.

## 3. 기능 요구사항

### 3.1 방향키 입력과 이동

| 입력 | 이동 | 바라보는 방향 |
| --- | --- | --- |
| 오른쪽 방향키 | 오른쪽 | 오른쪽으로 변경 |
| 왼쪽 방향키 | 왼쪽 | 왼쪽으로 변경 |
| 위쪽 방향키 | 위쪽 | 직전 좌우 방향 유지 |
| 아래쪽 방향키 | 아래쪽 | 직전 좌우 방향 유지 |
| 방향키 입력 없음 | 정지 | 직전 좌우 방향 유지 |

- 키를 누르면 해당 키의 입력 상태를 활성화하고, 놓으면 해제한다.
- 키를 누르고 있는 동안 매 프레임 이동한다. 운영체제의 키 반복 이벤트에 의존하지 않는다.
- 원본의 “토글(누르기)”은 한 번 눌러 계속 이동하는 방식이 아니라, **누르는 동안 이동하고 놓으면 중단하는 방식**으로 해석한다.
- 한 키를 놓아도 다른 방향키가 눌려 있으면 해당 방향의 이동은 유지한다.
- 프레임 간 경과 시간을 이용해 이동량을 계산하여 실행 속도에 따른 이동 속도 차이를 줄인다.

동시 입력 규칙은 원본에 명시되지 않아 다음 기준을 적용한다. 좌우 또는 상하의 반대 입력은 해당 축에서 상쇄한다. 가로·세로 입력이 함께 있으면 대각선 이동을 허용하되 전체 이동 속도는 단일 방향과 같게 유지한다. 좌우가 동시에 눌린 경우 바라보는 방향은 이전 값을 유지한다.

### 3.2 상태와 애니메이션

상태는 `IDLE`과 `MOVE`로 구분한다. 입력을 조합한 이동 벡터가 0이면 `IDLE`, 0이 아니면 `MOVE`이다. 화면 경계 때문에 실제 위치가 바뀌지 않더라도 이동 입력이 남아 있으면 `MOVE`를 유지한다.

스프라이트 행은 **이미지 좌상단 기준**으로 해석한다.

| 행 | 원본 정의 | 사용 조건 |
| --- | --- | --- |
| 1행 | 오른쪽 IDLE | `IDLE`, 오른쪽 방향 |
| 2행 | 왼쪽 IDLE | `IDLE`, 왼쪽 방향 |
| 3행 | 오른쪽 달리기 | `MOVE`, 오른쪽 방향 |
| 4행 | 왼쪽 달리기 | `MOVE`, 왼쪽 방향 |

- `MOVE`: 바라보는 방향에 해당하는 3행 또는 4행의 달리기 프레임을 순환한다.
- 위·아래 이동에서도 기존 좌우 방향의 이동 애니메이션을 사용한다.
- `IDLE`: 위치를 고정한 상태에서 바라보는 방향에 해당하는 1행 또는 2행의 IDLE 프레임을 순환한다. 프레임을 한 장에 고정하는 처리는 IDLE 애니메이션 요구사항을 충족하지 않는다.
- 상태나 좌우 방향이 바뀌면 해당 애니메이션의 시작 프레임과 누적 시간을 초기화한다.
- 애니메이션은 시간 간격에 따라 갱신하고 마지막 프레임 다음에 첫 프레임으로 돌아간다.

**애니메이션 선택 기준:** 정지 시 1·2행의 IDLE 애니메이션을 사용하고, 이동 시 3·4행의 달리기 애니메이션을 사용한다. 행은 현재 상태와 마지막 좌우 방향을 함께 기준으로 선택한다.

기존 예제의 프레임 크기 100 × 100과 8프레임 설정은 이미지 확인 후 적용한다. pico2d의 클리핑 좌표가 아래쪽 기준이므로, 이미지 높이와 행 높이를 이용해 위쪽 기준 1~4행의 좌표를 계산한다.

### 3.3 화면 경계 제한

- 캐릭터 중심점뿐 아니라 그려지는 스프라이트 전체가 화면 안에 있도록 제한한다.
- 화면 너비·높이가 `W`, `H`, 표시 크기가 `w`, `h`이면 중심 좌표를 다음 범위로 보정한다.
  - `w / 2 ≤ x ≤ W - w / 2`
  - `h / 2 ≤ y ≤ H - h / 2`
- 이동량을 적용한 다음 좌표를 보정하여 큰 이동량에서도 경계를 넘지 않게 한다.
- 경계에서 바깥 방향키를 계속 누르면 위치를 유지한다. 반대 방향으로 입력하면 즉시 화면 안쪽으로 이동한다.

### 3.4 배경과 종료

매 프레임 배경을 먼저 그리고 캐릭터를 그린다. 창 닫기 이벤트를 받으면 반복문을 종료하고 pico2d 캔버스를 정상적으로 닫는다.

## 4. 구현 구성

작은 프로그램 규모에 맞춰 입력, 갱신, 렌더링 역할을 함수로 분리한다. 별도 프레임워크나 복잡한 클래스 구조는 요구하지 않는다.

| 구성 | 책임 |
| --- | --- |
| 초기화 | 캔버스·리소스 생성, 위치·방향·입력 상태 설정 |
| 입력 처리 | 키 누름·해제 기록, 종료 이벤트 처리 |
| 상태 갱신 | 이동 벡터 계산, 방향·상태 결정, 위치와 경계 보정 |
| 애니메이션 갱신 | 경과 시간에 따른 프레임 순환 |
| 렌더링 | 배경 및 상태·방향에 맞는 캐릭터 표시 |

관리할 데이터는 위치 `x, y`, 눌린 방향키 집합, 좌우 방향, 현재 상태, 애니메이션 프레임과 누적 시간이다. 메인 반복문은 입력 처리 → 경과 시간 계산 및 갱신 → 렌더링 순서로 실행한다.

## 5. 완료 및 검수 기준

| 확인 항목 | 합격 기준 |
| --- | --- |
| 기본 표시 | 지정 배경과 캐릭터가 정상적으로 나타남 |
| 상하좌우 이동 | 각 방향키를 길게 누르면 끊김 없이 해당 방향으로 이동 |
| 키 해제 | 누른 키를 놓으면 해당 방향 이동이 중단됨 |
| 좌우 전환 | 좌·우 입력에 맞는 스프라이트 행을 사용 |
| 수직 이동 | 위·아래 이동 시 마지막 좌우 방향이 유지됨 |
| IDLE | 이동 입력이 없을 때 위치는 고정되고 방향에 맞는 1·2행의 프레임은 순환함 |
| 경계 제한 | 네 변과 네 모서리에서 캐릭터 전체가 화면 안에 유지됨 |
| 경계 탈출 | 경계에서 반대 방향 입력 시 정상적으로 안쪽 이동 |
| 동시 입력 | 반대 방향 상쇄 및 키별 해제가 일관되게 동작함 |
| 애니메이션 행 선택 | 정지 시 방향에 맞는 1·2행, 이동 시 방향에 맞는 3·4행을 사용함 |
| 정상 종료 | 창을 닫으면 오류 없이 종료됨 |

실제 실행 화면에서 위 항목을 수동 검수한다. 특히 IDLE에서도 프레임이 바뀌는지, 중심점만 제한하여 스프라이트가 잘리는 문제가 없는지 확인한다.

## 6. 개발 진행과 커밋 기준

원본의 요구대로 **단계별 개발 진행을 기록하고 커밋을 20회 이상 작성**한다. 각 커밋은 실제 코드·문서·검수 결과의 의미 있는 변경을 포함하고, 한글 메시지로 변경 내용과 목적을 설명한다. 빈 커밋으로 횟수를 채우지 않는다.

개발은 리소스 확인 및 초기 화면 → 입력 상태 관리 → 네 방향 이동 → 방향 전환 → 이동·IDLE 애니메이션 → 경계 제한 → 통합 검수 순서로 진행한다. 각 단계에서 동작 가능한 변경 단위를 나누어 커밋한다.

커밋 메시지 예: `방향키 해제 처리 추가: 키를 놓으면 해당 방향 이동 중단`. 최종 완료 시 기능 검수 결과와 커밋 수를 함께 확인한다.
